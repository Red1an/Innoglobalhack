# Прогоны моделей локально и в Colab

Для базового сравнения российских и китайских LLM через Caila откройте
[api_colab.ipynb](api_colab.ipynb) в локальном Jupyter (GPU не нужен).
Инструкция — [API_BENCHMARK.md](API_BENCHMARK.md). Шесть моделей получают тот же
`bench.PROMPT`, что локальные LLM; каждый законченный прогон автоматически
сохраняется в ClearML. Чистый тест подключается явно после завершения разметки.

Откройте colab.ipynb в локальном Jupyter из клона репозитория либо через ссылку
https://colab.research.google.com/github/Red1an/Innoglobalhack/blob/dev/research/experiments/colab.ipynb

Локально установите Python 3.10+ и CUDA-совместимый PyTorch по инструкции https://pytorch.org/get-started/locally/ и выберите это окружение как ядро Jupyter. Для локального Jupyter нужен пакет notebook или jupyterlab. В Colab выберите NVIDIA GPU. Ноутбук создаст отдельное окружение зависимостей, использующее torch ядра. CUDA и bitsandbytes должны поддерживать установленную GPU.

## Запуск LLM через Ollama на любой ОС

В ячейке настроек BACKEND выбирает способ запуска LLM. ollama работает на macOS, Linux и Windows, на CPU, Apple Silicon или NVIDIA, CUDA и bitsandbytes не нужны. transformers нужен NVIDIA GPU и используется по умолчанию в Colab. Установите и запустите приложение Ollama, зависимости стенда берутся из requirements-ollama.txt. Если в ядре нет pip, ноутбук ставит зависимости через uv.

В этом режиме доступны все четыре модели: char-lr, rumodernbert, t-lite-q8 и avibe-q8. rumodernbert обучается через torch на CUDA, Apple MPS или CPU, на CPU обучение займёт часы. t-lite-q8 это T-lite 2.1 в GGUF Q8_0 (8,7 ГБ), avibe-q8 это avibe в GGUF Q8_0 (8,4 ГБ). Официального GGUF у avibe нет, используется конвертация NightForger/avibe-GGUF, поэтому её результат может немного отличаться от исходной модели. Каждой LLM нужно около 9–10 ГБ памяти, модели загружаются по очереди.

Перед прогоном стенд проверяет, есть ли модель в Ollama. Если GGUF уже скачан, укажите в словаре GGUF путь к файлу или к его папке, например папке модели в LM Studio, и стенд импортирует его в Ollama. Иначе модель скачается с Hugging Face. Ответ ограничен JSON-схемой, температура 0, seed 42, контекст равен --max-length. Если объявление не помещается в контекст, прогон останавливается, а не обрезает текст. Локальный путь к файлу не входит в конфигурацию прогона, веса опознаются по digest модели в Ollama.

## Запуск из терминала

run_all.py делает то же, что ноутбук: готовит набор, по очереди гоняет модели с прогрессом, выгружает каждый прогон в ClearML и пишет results.csv. Каталоги данных и прогонов совпадают с ноутбуком. Зависимости ставятся один раз:

uv venv .venv-bench --python 3.10 && UV_HTTP_TIMEOUT=600 uv pip install --python .venv-bench/bin/python -r requirements-ollama.txt "pyarrow>=19,<24" clearml==2.2.0

Прогон исходного train организаторов с test_gold на всех четырёх моделях:

.venv-bench/bin/python run_all.py --dataset raw-gold --participant member2

Для нового train добавьте в PRESETS файла run_all.py пару (новый train, data/test/test_gold.parquet) под своим именем и запустите с ним и своим --participant. --models выбирает модели, --no-upload отключает ClearML. Повторный запуск продолжает незавершённый прогон LLM.

Одну модель можно прогнать и напрямую:

python bench.py run --model t-lite-q8 --data <каталог prepare> --out runs/t-lite-q8 --gguf <путь к GGUF>

## Два участника

В ячейке настроек первый задаёт DATASET = "old", PARTICIPANT = "member1", второй DATASET = "gold", PARTICIPANT = "member2". RUN_GROUP обозначает конфигурацию, например baseline. В обоих случаях общий PROJECT = "avito-microcategories".

Доступны old (исходные train/test, тест 208 строк), processed (очищенные train/test), gold (очищенный train и test_gold.parquet, тест 139 строк), custom (явные пути CUSTOM_TRAIN и CUSTOM_TEST). Выбор gold использует закреплённый командой эталон. Исходные файлы остаются в data/. Для каждого набора создаются train/dev/test JSONL и manifest с хешами. Изменение исходных файлов создаёт новую версию набора.

Сравнение old и gold одновременно меняет train, состав теста и разметку. Оно показывает качество на двух версиях данных. Для измерения эффекта изменения train используйте custom с одним фиксированным тестом. Пороги и параметры выбирайте на dev. Семантические дубликаты автоматически не исключаются.

С `test_gold.parquet` стенд исключает из train и dev также совпадения после той же очистки, что использовалась для `train_dedup_v1`. Gold сохраняется целиком. Манифест содержит число исключённых строк, а `gold_overlaps.csv` связывает их с номерами строк gold. Для этой версии проверки используется новый каталог подготовленных данных и прогонов.

Подготовка принимает train/test в JSONL или Parquet, поля description, labels или found_microcategories либо категории y_102…y_106. В исходных данных нет mcId, поэтому явно принимаем источник 101. Энкодер и char-LR поддерживают этот источник, выбирают дополнительные 102–106. Новые источники требуют адаптации обучаемых моделей.

## ClearML

Участники должны входить в один workspace ClearML и использовать каждый свои API credentials. Локально сохраните выданную конфигурацию в ~/clearml.conf либо используйте CLEARML_CONFIG_FILE или переменные CLEARML_API_ACCESS_KEY и CLEARML_API_SECRET_KEY. В ноутбуке скрытые поля появляются при отсутствии конфигурации. Перед прогонами проверяется авторизация через API.

AUTO_UPLOAD = True автоматически отправляет каждый завершённый прогон. INCLUDE_DATASET = True отправляет также полные тексты и сплиты в ваш ClearML workspace. Для защиты сохраняются run.json с параметрами/версиями/промптом, protocol.py с кодом прогона, manifest.json, metrics.json, predictions.jsonl, errors.jsonl и train/dev/test.jsonl. Итоговые метрики доступны в Scalars, таблица предсказаний в Plots, файлы в Artifacts. Checkpoint энкодера хранится локально.

Выгрузка синхронная. После неё выводится ссылка задачи. При сбое вызовите export_model("avibe") или другую модель после восстановления подключения. Каждый повтор создаёт новую задачу. Повторный run_model использует завершённые предсказания из прежнего каталога, если конфигурация совпадает. Если изменили код или параметры, задайте новый RUN_GROUP. Частичное обучение энкодера возобновлять нельзя, используйте новый RUN_GROUP.

Локально нужна сеть для скачивания моделей и связи с ClearML. Код одинаковый для Colab и локального запуска, GPU-результаты определяются реальным железом. У LLM NF4/FP16, greedy и общий системный промпт. Метрики micro-F1, precision, recall, exact match, per-category F1, invalid rate и задержка p50/p95. Контекстный срез определяется эвристикой.

## Проверка

python -m unittest discover -s research/experiments -p "test_*.py"

GPU-прогоны требуют проверки на NVIDIA GPU. Перед выгрузкой проверяются хеши данных и соответствие предсказаний. Не сохраняйте ключи в ноутбуке. Каталоги результатов, окружения, конфигурация ClearML и веса исключены из Git.
