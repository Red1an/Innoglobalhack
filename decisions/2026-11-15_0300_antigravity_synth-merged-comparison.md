## 2026-11-15 04:01 МСК | решение | классификация | глобальное
Что: Спроектирована двухступенчатая гибридная схема классификации (обученная на `train_relabel_v2_synth_v1` модель + точечный арбитраж сложных случаев через LLM с модульным динамическим промптом) и протокол проверки из 7 стресс-срезов перед отправкой приватного теста.
Почему: (1) Чистая локальная или API LLM в zero-shot режиме не использует знания из 5 311 вычищенных строк `train_relabel_v2_synth_v1`, не имеет настраиваемых порогов вероятности, медленно работает на батче и даёт избыточные ложные срабатывания (FP) на общих фразах («ремонт санузла под ключ»). (2) Обученная модель (`RuModernBERT` / `Giga-Embeddings` / `char-LR`) мгновенно (< 20 мс) и с высокой точностью (~95% Precision) закрывает 75–80% очевидных объявлений, но уязвима к сложным отрицаниям, чужой работе и технадзору. (3) Динамическая сборка промпта из правил только для кандидатов в «серой зоне» (`0.25 <= p_k <= 0.72`) или при срабатывании маркеров-ловушек (`не/нет/кроме/заказчик/партнер/технадзор/дизайн/под покраску/выравнивание`) решает проблему контекстных ловушек и сокращает число обращений к LLM в 4–5 раз.
Альтернативы: (1) Только локальная LLM на все 100% строк — отвергнуто из-за просадки Precision на 5–10 п.п., отсутствия порогов и долгого инференса на пакете; (2) Динамический промпт с подстановкой похожих примеров из train по TF-IDF — отвергнуто по рекомендации ментора из-за риска копирования чужих меток.
Результат: Сформирован план валидации на 7 срезах (`test_gold`, 15 сложных пустых, 66 реальных одиночных `104≠105`, 224 строки синтетического зонда с ловушками, 6 строк с латинскими омоглифами, проверка `mcId != 101`, аудит расхождений между классификатором и LLM на привате) и стратегия использования 2–3 попыток сдачи приватного CSV (строгий Precision-first против варианта с учётом тегов/хвостов).
Где: decisions/2026-11-15_0300_antigravity_synth-merged-comparison.md; decisions/2026-11-14_1832_codex_mentor-rules.md; research/experiments/bench.py.
