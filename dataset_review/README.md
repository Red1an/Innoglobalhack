# Проверка датасета

В этой папке команда анализирует данные кейса и вручную проверяет разметку.

## Как подготовить окружение

Положите файлы кейса в папку `data/raw` в корне репозитория. Папка должна содержать файлы `public-train-annotated.jsonl` и `public-test-dataset.parquet`. Git не хранит эти файлы, потому что папка `data` указана в `.gitignore`.

Создайте окружение и установите зависимости командами из корня репозитория:

```bash
uv venv .venv
uv pip install --python .venv/bin/python -r dataset_review/requirements.txt
```

Затем откройте ноутбук `dataset_review/01_dataset_exploration.ipynb` и выполните все ячейки по порядку.

## Что лежит в папке

* Ноутбук `01_dataset_exploration.ipynb` описывает данные и сохраняет файлы для ручной проверки.
* Папка `review` содержит таблицы для ручной проверки. Каждая строка таблицы описывает одну пару из объявления и микрокатегории.
* Файл `requirements.txt` перечисляет библиотеки, которые нужны ноутбуку.

## Как проверять разметку вдвоём

Ноутбук распределяет объявления между двумя проверяющими по чётности идентификатора. Первый проверяющий берёт строки со значением `reviewer_1` в колонке `reviewer`, а второй проверяющий берёт строки со значением `reviewer_2`.

В колонку `decision` нужно записать 1, если исполнитель действительно предлагает услугу этой микрокатегории и черновик нужен, и 0, если черновик не нужен. В колонку `comment` нужно коротко записать причину решения, особенно если случай спорный.

Повторный запуск ноутбука перезаписывает файлы в папке `review`. Чтобы не потерять ручные решения, скопируйте файл перед проверкой и работайте с копией, в имени которой есть ваше имя, например `test_duplicate_conflicts_ivan.csv`.

Два человека не должны одновременно менять один ноутбук, потому что Git плохо объединяет изменения в ноутбуках. Для своих экспериментов создайте копию ноутбука с вашим именем.
